# Teamwork

Throughout the project, we have primarily coordinated our work through GitHub, using issues to distribute tasks and feature branches and pull requests to manage contributions. This allowed us to work on different parts of the application in parallel while keeping changes relatively isolated.

With every release, we became more deliberate about how we organized this work. For example, we introduced a `CONTRIBUTING.md` file describing our development practices, as well as issue and pull request templates to encourage more consistent issues and PRs. We also started making greater and more deliberate use of pull request reviews, so we could communicate and assign responsibility more effectively. These practices helped establish a more predictable workflow and made it easier to understand what individual contributions were intended to accomplish.

However, we learned that introducing tools and guidelines does not automatically ensure that they are used consistently. Some issues lacked sufficient detail (see issue [#87](https://git.ntnu.no/IT1901-2026-groups/gr2607/issues/87) for example), and contribution guidelines were not always followed. This occasionally made it harder to understand the scope of a task or review a contribution. We also experienced situations where several changes had to be integrated and reviewed at once, increasing the coordination required.

One important lesson was that effective teamwork requires more than dividing tasks between group members. Tasks need clear objectives, and team members need to communicate about dependencies and implementation decisions before working independently. In future projects, we would establish these practices earlier and make more consistent use of them throughout development.
